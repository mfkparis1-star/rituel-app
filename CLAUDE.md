# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**Rituel** — a French-first skincare/beauty mobile app (iOS-primary, Android secondary). Expo SDK 54 + React Native 0.81 + expo-router, TypeScript strict, Supabase backend, RevenueCat monetization. AI features (skin analysis, makeup, product scan, routine optimization, translation) are powered by Claude via a server-side Supabase edge proxy — the Anthropic key never reaches the client.

## Commands

```bash
npm start            # expo start (Metro dev server)
npm run ios          # expo start --ios
npm run android      # expo start --android
npx tsc --noEmit     # typecheck (CI-equivalent gate — there is no separate lint/test setup)
```

There is **no test suite, ESLint config, or build script** in package.json. `npx tsc --noEmit` is the only automated check — run it before considering work done. Builds go through EAS (`eas build`), configured in `eas.json` (development / preview / production channels; iOS submit credentials live there). Native code (`android/`, `ios/`) is generated by prebuild and gitignored; most changes are JS/TS and ship via expo-updates OTA.

`.npmrc` sets `legacy-peer-deps=true` — npm installs will fail without it.

## Environment

Client env vars must be prefixed `EXPO_PUBLIC_` (see `.env.example`):
- `EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_ANON_KEY` — Supabase
- `EXPO_PUBLIC_REVENUECAT_IOS_KEY` — RevenueCat (starts with `appl_`)
- `EXPO_PUBLIC_SENTRY_DSN` — optional; Sentry only inits if present

`lib/supabase.ts` falls back to placeholder credentials if env vars are missing so the app renders instead of crashing — a missing-config bug shows up as failing auth/DB calls, not a white screen.

## Architecture

### Routing (expo-router, file-based)
- `app/_layout.tsx` — root Stack. Wraps app in Sentry, GestureHandler, SafeArea. Registers a notification-response listener that deep-links the evening reminder to the guided ritual. `paywall` and `add-product` are modal presentations.
- `app/(tabs)/_layout.tsx` — 5 visible tabs (Home, Archive/Products, AI Studio, Community, Profile/auth). Screens with `href: null` (skin-analysis, makeup, routine, compatibility) are routable but hidden from the tab bar. The tab layout owns the auth session and force-redirects un-onboarded signed-in users to `/onboarding`.
- Typed routes are **off** — route pushes use `as any` casts deliberately (see `BUILD_NOTES.md`).
- `*.bak` and `*.phase16c.bak` files in `app/` are dead snapshots; ignore them.

### AI layer — the single most important pattern
All AI goes through **one client function: `utils/aiProxy.ts → callClaudeProxy(endpoint, body, timeoutMs)`**. It posts to the Supabase edge function `claude-proxy` with the user's access token and an `x-rituel-endpoint` header (for per-feature rate limiting). It centralizes timeout/abort, 429/401/403/upstream error mapping into typed `AIProxyError` codes, and `localizedAIError(code, lang)` gives fr/en/tr messages. `safeJsonParse` strips markdown fences from model output.

Each feature is a thin wrapper in `utils/` that owns its prompt + result type and calls the proxy: `skinAnalysis.ts`, `makeupAI.ts`, `productAI.ts`, `routineAI.ts`, `translate.ts`, `reflection.ts`, `skinProfileAnalysis.ts`, `compatibility.ts`. When adding an AI feature: add the endpoint to the `Endpoint` union in `aiProxy.ts`, mirror it in the edge function's rate limiter, and write a wrapper that builds the prompt and parses with `safeJsonParse`. Prompts instruct the model to return raw JSON (no code fences).

### Monetization (RevenueCat + credits, no server columns)
- `hooks/usePremium.ts` — premium is derived **solely** from RevenueCat `CustomerInfo.entitlements.active['Rituel Pro']`. There is no `profiles.is_premium` column and no webhook.
- `hooks/useAIUnlock.ts` — gating model: premium users are always unlocked; free users spend **1 credit per AI result**, tracked per `scope:resultId` in AsyncStorage, refund-aware. `utils/credits.ts` is the credit balance (Supabase `user_credits.balance`, AsyncStorage-cached, clamped ≥ 0).

### Data & backend (Supabase)
- `lib/supabase.ts` — single client. Native uses AsyncStorage for session persistence; web uses `detectSessionInUrl` for OAuth.
- Custom hooks in `hooks/` are the data-access layer (one concern each: `useProfile`, `useCheckins`, `useScore`, `useRoutineSteps`, `useFavoriteProducts`, `useMemory`, etc.). Prefer adding/using a hook over inlining Supabase queries in screens.
- `supabase/migrations/` — SQL migrations (RLS hardening, community, check-ins, `profiles.onboarded`). `supabase/functions/` — edge functions (`delete-user` is in-repo; the `claude-proxy` function is deployed separately).

### i18n (fr is source of truth)
- `utils/i18n/` (locales + `t`), surfaced via `hooks/useLanguage.ts`. Three languages: `fr` (default/canonical), `en`, `tr`. TS-enforced key parity across locales.
- Locale resolution order: AsyncStorage → `profile.language` → device locale → `fr`.
- **DB stores canonical French**; non-French display is translation-only (no translated columns). User-facing strings in screens must go through `t(...)`, not hardcoded literals.

### Theme
- `theme/tokens.ts` exports `C` (colors — `copper`/`appBg`/`border` etc.), `G`, `R`, `Sh`, `Sp`, `Type`. Import via `theme` (`import { C } from '../theme'`). Brand palette is warm/cream (`#F6F1EC` bg, copper accents). UI is light-mode only (`userInterfaceStyle: light`).

## Hard rules

- **Writing Python patch scripts:** always write to a file with a heredoc — `cat > /tmp/x.py << 'EOF'` … `EOF`. Never use inline `python3 -c "..."`; zsh mangles it.
- **Pushing:** the push target is `git push origin main:phase15-rebuild` (local `main` → remote `phase15-rebuild`).
- **AI calls:** only through the `claude-proxy` edge function with the `x-rituel-endpoint` header (i.e. via `callClaudeProxy`). Never call Anthropic from the client; never introduce `EXPO_PUBLIC_ANTHROPIC_API_KEY` or any client-side API key.
- **Errors:** 429 (and all `AIProxyError` codes) must be localized in all three languages, FR first — extend the maps in `localizedAIError` (`utils/aiProxy.ts`).
- **`.bak` files** are gitignored (`*.bak` in `.gitignore`) — they are local snapshots and must never be committed.

## Project state & conventions

- `docs/PROJECT_STATE.md` is the canonical roadmap snapshot — phases are numbered (currently through Phase 19 i18n complete; Phase 15.2+ RevenueCat and Phase 20/21 Optical Intelligence pending). Other `docs/PHASE_*.md` and `*_CHECKLIST.md` files hold per-phase detail. Read PROJECT_STATE first to orient on what's done vs. planned. Some docs contain Turkish notes (`BUILD_NOTES.md`).
- Commit style (see `git log`): `type(scope) — short description`, e.g. `fix(makeup) — pass user language`. Conventional-ish, em-dash separator.
- Code style: error handling is defensive and silent-failing (try/catch returning safe fallbacks, lazy `require` for native modules that may be absent in older binaries) so the app degrades rather than crashes. Match this when touching startup, native-module, or network paths.
